# autodl-monitor

AutoDL GPU 资源监控与同配置自动克隆工具。

监控 AutoDL 指定地区的 GPU 资源，发现可租机器后弹窗提醒，或按设定的费用上限自动克隆已有实例，同时复制系统盘和数据盘。

> **项目来源：本项目基于 [Jiayi-Fu/autodl-gpu-monitor](https://github.com/Jiayi-Fu/autodl-gpu-monitor) 进行二次开发。**
> 在原项目的资源监控、登录和自动新建实例功能基础上，增加动态地区解析、机器状态核验、macOS 弹窗、同配置克隆、费用筛选与复制进度跟踪。感谢原作者提供的基础代码。

默认配置为**仅监控，不下单**。自动克隆需要选择源实例、设置费用上限，并在启动时输入 `CLONE` 确认；完成一次提交后不再继续创建实例。

## 功能与运行方式

| 运行方式 | 用途 | 是否创建付费实例 |
| --- | --- | --- |
| 单次查询 | 查询一次资源并退出 | 否 |
| 持续监控 | 定时检查，有合适机器时弹窗或微信提醒 | 否 |
| 自动克隆 | 选择已有源实例，等待符合配置和价格条件的机器，克隆一次并跟踪复制进度 | 是，启动时须确认 |
| 普通新建 | 使用配置中的镜像创建一个新实例，沿用上游功能 | 是，与克隆流程不同 |

主要功能：

- **动态地区选择**：通过平台地区列表解析“北京B区”等名称，查询该地区的全部子区。
- **核对具体机器**：每轮都检查机器明细，排除不可租状态、实例容量已满和空闲卡数不足的机器。
- **本机提醒**：macOS 原生弹窗和提示音，不需要配置微信；重复库存提醒默认间隔至少 5 分钟。
- **同配置克隆**：每次启动动态选择源实例，复制系统盘和数据盘，按源实例的资源规格筛选目标。
- **费用筛选**：克隆下单前读取平台价格预览，计入账号折扣及数据盘费用。
- **跟踪克隆结果**：区分“请求受理”和“复制完成”，完成、失败或进度待确认时分别提醒。
- **异常处理**：查询支持超时和有限重试；付费请求结果不确定时停止，不盲目重复提交。

## 快速开始

### 1. 准备环境

推荐使用 **Python 3.12 + [uv](https://docs.astral.sh/uv/)**。macOS 可使用全部本机弹窗功能。

克隆本仓库并进入项目目录，也可以下载源码后手动进入：

```bash
git clone https://github.com/Sykerai/autodl-monitor.git
cd autodl-monitor
```

项目固定了部分依赖版本，建议使用独立的 Python 3.12 环境。启动脚本不会依赖终端当前激活的是哪一个 Python。

### 2. 创建本地配置

**首次使用、且目录中还没有 `config.json` 时**，复制示例配置：

```bash
cp config.example.json config.json
```

已有配置请直接编辑，避免覆盖保存的登录信息。示例配置使用：

| 项目 | 示例值 |
| --- | --- |
| 运行模式 | 仅监控 `monitor_only` |
| 地区 | 北京 B 区 |
| GPU | RTX 5090，每台 1 张 |
| 检查间隔 | 30 秒 |
| 本机弹窗 | 开启，macOS 可用 |
| 微信推送 | 未配置 |
| 克隆费用上限 | 未设置，需自行指定 |

示例中的地区和 GPU 可在 `config.json` 修改，也可使用命令临时覆盖。

### 3. 启动并完成登录

macOS / Linux：

```bash
./run.sh
```

脚本会在需要时用 uv 创建 `venv` 并安装依赖，再启动程序，无需手动激活虚拟环境。

首次登录会显示微信二维码：

1. 使用微信扫描电脑上的二维码。
2. 按手机页面提示完成登录或授权。
3. 保持二维码窗口打开即可，程序会自动检测结果并关闭窗口。
4. 登录成功后，令牌保存到本地 `config.json`，继续执行当前任务。

扫码等待上限为 3 分钟。需要重新登录时执行：

```bash
./run.sh --login
```

此命令登录后会继续按配置运行；初次使用建议保留 `mode: "monitor_only"`。

### 4. 确认监控和提醒

只查询一次，不下单、不弹窗、不发送微信：

```bash
./run.sh --once
```

测试本机弹窗和提示音，不登录、不查询库存、不下单：

```bash
./run.sh --test-popup
```

临时查询其他型号：

```bash
./run.sh --region 北京B区 --gpu "RTX 4090" --interval 30
```

按 **Ctrl+C** 停止程序。修改代码或配置后，需要停止旧进程并重新启动，运行中的进程不会自动加载新版本。

### 手动启动与 Windows

不使用启动脚本时，macOS / Linux 可以手动创建环境：

```bash
uv venv --python 3.12 venv
uv pip install --python venv/bin/python -r requirements.txt
./venv/bin/python main.py --help
```

Windows 不使用 `run.sh`，可在 PowerShell 中使用对应的环境路径：

```powershell
uv venv --python 3.12 venv
uv pip install --python .\venv\Scripts\python.exe -r requirements.txt
.\venv\Scripts\python.exe main.py --help
```

后文的 `./run.sh 参数`，也可替换为相应环境中的 `python main.py 参数`。本机弹窗目前只支持 macOS；其他平台可使用终端输出和 Server酱推送。扫码登录需要能够显示二维码的图形桌面会话。

## 自动克隆已有实例

适用于：原实例的环境和数据已经配置好，但所在主机没有空闲 GPU，希望在**同一地区**找到另一台符合配置的机器后自动克隆。

### 第一步：查看或选择源实例

读取账号当前的实例列表：

```bash
./run.sh --list-instances
```

动态选择源实例并预览克隆计划：

```bash
./run.sh --clone-preview
```

程序会显示实例列表，输入序号即可选择。每次启动都可以重新选择，不必把来源写死在代码中。选定后，本轮任务固定使用该源实例，不会中途自动换成其他实例。

预览会显示源实例 ID、地区、GPU、CPU、内存和磁盘容量，**不会下单，也不会查询目标库存**。

也可以直接指定来源；将 `INSTANCE_ID` 替换为列表中的真实实例 ID：

```bash
./run.sh --clone-preview --source INSTANCE_ID
```

### 第二步：设置上限并启动自动克隆

例如，接受的费用折算上限为 **3 元/小时**：

```bash
./run.sh --clone --max-price 3
```

启动后依次完成：

1. 从实时列表中选择源实例。
2. 核对程序显示的配置、复制范围和费用上限。
3. 输入大写 `CLONE` 确认；其他输入表示取消。
4. 程序持续检测，找到满足条件的机器后自动提交克隆，无需再次点击弹窗或手动下单。
5. 请求受理后不再下单，只跟踪新实例创建和数据复制进度。
6. 数据复制完成后弹窗提示，并结束本轮任务。

如果已经在 `config.json` 的 `clone` 部分保存上限，例如：

```json
"clone": {
  "source_instance_uuid": "",
  "max_price_per_hour": 3
}
```

后续只需运行：

```bash
./run.sh --clone
```

`source_instance_uuid` 留空表示每次选择。命令中的 `--source`、`--max-price` 仅影响本次运行，不会改写配置文件。

### “同配置”具体匹配什么

| 项目 | 克隆目标要求 |
| --- | --- |
| 地区 | 与源实例同地区，包含平台当前列出的全部子区 |
| GPU | 型号、每卡显存、卡数一致 |
| CPU | 核数一致，不要求物理 CPU 品牌型号相同 |
| 内存 | 容量一致 |
| 架构 | CPU 架构、芯片厂商一致，CUDA 支持兼容源环境 |
| 系统盘 | 当前支持标准 30 GB 系统盘，复制原系统环境 |
| 数据盘 | 复制数据，总容量与源实例一致；按目标基础容量计算所需扩容量 |
| 主机 | 不要求与源实例为同一台物理主机 |

例如，源实例的数据盘为 **50 GB 基础容量 + 100 GB 扩容 = 150 GB**，目标也需要达到 150 GB 总容量。程序不会只创建默认数据盘后直接拷贝，避免因容量不足导致复制失败。

克隆使用源实例的环境信息；普通新建所用的 `image` 配置不会替换克隆来源。

### 源实例要求与任务边界

- 使用普通容器实例，源实例必须处于**已关机**状态，计费方式为**按量计费**。
- 当前不支持包年包月源实例、非标准系统盘或容器实例 Pro 的自动克隆。
- 系统盘和数据盘都会复制；程序不自动关闭、释放或删除源实例。
- 下单前会再次读取源实例状态和配置。源实例配置发生变化时停止，需要重新选择。
- 自动克隆需要在交互终端确认，不支持跳过确认后静默后台启动。
- 请求受理后不再创建第二个实例；“数据复制失败”也不会触发重新购买。
- 新实例运行后会按平台规则计费。停止脚本、关闭弹窗或达到进度跟踪时限，都不会自动关闭新实例。

## 费用上限怎么算

**费用上限用于筛选克隆目标的租用单价，不是整个任务的总预算。**

程序使用平台的价格预览，比较：

```text
每小时折算费用 = GPU 小时费 + 扩容数据盘日费 ÷ 24
```

假设价格预览返回：

| 费用 | 假设值 |
| --- | ---: |
| GPU 小时费 | 2.88 元/小时 |
| 扩容数据盘日费 | 0.67 元/天 |
| 每小时折算费用 | 约 2.91 元/小时 |

设置 `--max-price 3` 时，这台机器符合费用条件；高于 3 元/小时则跳过，继续等待。以上数字仅用于说明计算方式，不代表平台实时价格。

需要注意：

- 预览会考虑平台返回的账号折扣，不直接使用机器列表原始标价。
- 数据盘仍按平台实际的日费规则结算，“÷24”只用于统一筛选口径，不代表数据盘改为按小时收费。
- 上限不会限制累计支出，也不会在累计花费达到 3 元时自动关机。
- 价格预览与提交是两个请求，客户端筛选不构成平台原子锁价，实际账单以 AutoDL 为准。
- **该上限只用于自动克隆，不作用于 `monitor_and_buy` 普通新建模式。**

## 如何理解终端和弹窗

### 库存数字

```text
北京B区 | RTX 5090 | 总计 2544 张，空闲 1 张
```

这是地区汇总接口的一次快照，表示该型号的总卡数和汇总空闲卡数，数字仅为输出示例。

程序随后检查具体机器的状态、实例容量和卡数。在克隆模式中，还会检查同配置要求和价格。因此：

- 汇总有空闲，不保证稍后一定能找到可租机器；库存可能已经变化，两个接口也可能更新不同步。
- 汇总为 0，也不会跳过机器明细检查；提醒和下单依据本轮可租机器明细判断。
- 机器明细中存在正的空闲卡数，但机器不可租或实例容量已满时，不会被算作可租机器。

出现差异时，终端会显示明细检查耗时及排除统计。克隆模式还会显示：

```text
可租机器 5 台 → 同配置 2 台 → 符合费用上限 1 台
```

这表示只有最后 1 台满足本轮自动克隆的全部筛选要求。即使筛选通过，实际提交时仍可能因其他用户抢先租用而失败。

### 弹窗分别表示什么

| 弹窗 | 含义 |
| --- | --- |
| 发现空闲 GPU | 本轮机器明细发现满足当前模式要求的机器 |
| 克隆请求已受理 | 平台返回新实例 ID，尚未确认数据复制完成 |
| 克隆成功 · 数据复制完成 | 新实例已就绪，且平台报告数据盘复制成功 |
| 克隆或数据复制失败 | 平台报告创建或复制失败，需要到官网查看详情 |
| 克隆进度待确认 | 查询中断、登录失效或达到跟踪时限，当前无法确认最终结果 |

本机弹窗和提示音默认开启，无需 SendKey。点击“知道了”仅关闭窗口，不启动或取消下单。

库存提醒默认至少间隔 5 分钟，窗口未关闭时不叠加新窗口；无人操作时窗口 5 分钟后自动关闭。克隆结果提醒会替换旧窗口，不受库存提醒冷却限制。

克隆请求受理后，默认每 **10 秒**查询一次新实例状态，最长跟踪 **1 小时**。只有实例处于运行中或已关机，且数据盘复制状态为 `Succeed`，才报告完成。

按 Ctrl+C 停止本地跟踪，不会取消平台上的克隆。遇到“进度待确认”或提交结果不确定，请先到官网核查新实例，再决定是否重新运行，避免重复创建。

### 微信推送

可在 [Server酱](https://sct.ftqq.com/) 获取 SendKey，填入 `notification.sendkey`。

留空表示不发送微信消息，不影响终端和本机弹窗。发送失败不会导致重复购买。配置截图可参考 [Server酱登录](assert/server_login.png)和 [SendKey](assert/server_sendkey.png)。

## 配置说明

完整可复制模板见 [`config.example.json`](config.example.json)。登录后的 `config.json` 是个人本地配置，不应提交到公开仓库。

### 运行模式

| `mode` | 行为 |
| --- | --- |
| `monitor_only` | 默认模式：持续监控与提醒，不下单 |
| `monitor_and_clone` | 动态选择源实例并确认后，监控并克隆一次 |
| `monitor_and_buy` | 使用配置镜像普通新建实例，不复制既有实例的数据 |

运行 `./run.sh` 会执行配置中的模式。本文快速开始使用默认的 `monitor_only`；`--clone` 可临时切换到自动克隆，`--once` 则只查询、不下单。

**普通新建模式会创建付费实例，且没有克隆流程的价格上限和启动确认。** 如果需要保留已有环境和数据，应使用克隆流程。

### 地区、GPU 和镜像

| 字段 | 含义 | 省略时的默认值 |
| --- | --- | --- |
| `authorization` | 登录令牌，扫码后自动保存 | `""` |
| `region_names` | 地区名称列表，例如 `["北京B区"]`，动态解析全部子区 | `[]` |
| `region_sign_list` | 可选的精确子区代码；已被名称覆盖的代码不重复查询 | `[]` |
| `gpu.model` | GPU 型号，需与平台返回名称一致 | 必填 |
| `gpu.num` | 单台实例需要的 GPU 卡数，1–8 | `1` |
| `image.private_image_uuid` | 普通新建使用的私有镜像 UUID | `""` |
| `image.autodl_image` | 普通新建使用的公共镜像地址 | `""`，下单时使用内置镜像 |

地区名称和代码都为空时，沿用原项目的型号预设地区。推荐填写地区名称，减少旧代码映射遗漏新增子区的情况。

例如，`region_names: ["北京B区"]` 表示整个地区；`region_sign_list: ["bj-B1"]` 仅表示单个子区。名称解析以平台当前列表为准；找不到指定名称时会提示错误，不会静默改查其他地区。

镜像配置仅用于普通新建。选择方法可参考 [公共镜像截图](assert/auto_image.png)和 [私有镜像截图](assert/auto_private_image.png)。

### 查询设置

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `monitor.interval` | 一轮检查结束后等待多久再查，秒 | `30` |
| `monitor.retry_interval` | 明确下单失败后的等待时间，秒 | `10` |
| `monitor.request_timeout` | 单次 HTTP 请求超时，秒 | `15` |
| `monitor.max_retries` | 查询发生网络异常时的额外重试次数，0–5 | `2` |
| `monitor.stop_after_found` | 仅监控发现合适机器后是否退出 | `false` |

机器列表每页请求 90 条，并遵循服务端实际分页大小。连续查询失败会延长下一轮间隔，上限为 300 秒。实际检查周期还包含接口请求和筛选耗时，并非严格每 30 秒开始一轮。

### 克隆设置

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `clone.source_instance_uuid` | 固定源实例 ID；留空则每次选择 | `""` |
| `clone.max_price_per_hour` | 每小时费用折算上限；未设置时不能启动付费克隆 | `null` |
| `clone.status_interval_seconds` | 请求受理后的进度查询间隔，秒 | `10` |
| `clone.completion_timeout_seconds` | 最长进度跟踪时间，秒 | `3600` |

这些设置不会自动开启克隆；仍需选择克隆模式并在交互终端确认。

### 通知设置

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `notification.desktop_popup` | macOS 本机弹窗和提示音 | `true` |
| `notification.popup_cooldown_seconds` | 库存弹窗最短重复间隔，秒 | `300` |
| `notification.sendkey` | Server酱 SendKey，空时不发微信 | `""` |
| `notification.cooldown_seconds` | 可用资源微信提醒最短重复间隔，秒 | `300` |

## 命令速查

以下命令在项目目录运行；除测试弹窗和帮助外，查询类命令需要有效登录状态。

| 命令 | 用途 |
| --- | --- |
| `./run.sh` | 执行配置中的模式，默认仅监控 |
| `./run.sh --once` | 只查一轮，不下单或发送通知 |
| `./run.sh --region 北京B区 --gpu "RTX 5090"` | 临时覆盖普通监控的地区和型号 |
| `./run.sh --interval 15` | 本轮任务使用 15 秒检查间隔 |
| `./run.sh --login` | 重新扫码，然后继续执行当前模式 |
| `./run.sh --test-popup` | 测试本机弹窗和提示音 |
| `./run.sh --no-popup` | 本次关闭本机弹窗 |
| `./run.sh --list-instances` | 读取当前账号的源实例列表 |
| `./run.sh --clone-preview` | 动态选择源实例并预览配置，不下单 |
| `./run.sh --clone --max-price 3` | 选择源实例，按 3 元/小时折算上限监控并克隆一次 |
| `./run.sh --clone --source INSTANCE_ID` | 本次指定源实例，费用上限从配置读取 |
| `./run.sh --clone --once --source INSTANCE_ID` | 只查询一轮符合源配置的目标，不下单 |
| `./run.sh --help` | 查看所有参数 |

`INSTANCE_ID` 需要替换为真实 ID。克隆的地区、GPU 和卡数由源实例决定，不能同时传入 `--region` 或 `--gpu`。`--max-price` 只用于克隆，不能为普通新建设置上限。

## 常见问题

### `ModuleNotFoundError: No module named 'requests'`

当前终端使用的 Python 环境中没有安装项目依赖。优先使用：

```bash
./run.sh
```

已有 `venv` 时，也可直接运行 `./venv/bin/python main.py`。不要只用不确定指向哪个环境的 `python main.py`。

### 扫码后看起来没有反应

确认已在手机上完成登录或授权，而不只是打开小程序。二维码窗口可以保持打开，程序会继续检测。超时后重新运行获取新二维码；已有令牌失效时使用 `--login`。

### 汇总显示空闲 1 张，却提示没有可租机器

地区汇总和机器明细来自不同请求，库存变化或更新不同步时可能不一致。程序还会排除不可租状态和容量已满的机器；克隆时继续检查同配置及费用上限。查看后续的筛选统计，以本轮机器明细为准。

### 明明有同型号 GPU，为什么不能克隆

同型号不一定同配置。目标的显存、CPU 核数、内存、架构、磁盘容量和 CUDA 支持都需要满足源实例要求，价格也不能超出上限。程序不会自动降配或改成其他地区。

### 弹窗出现后，需要点“知道了”才能下单吗

不需要。仅监控模式不会下单；自动克隆在启动时输入 `CLONE` 确认后，检测到符合条件的机器就会自动提交。点击弹窗只关闭提醒。

### 收到新实例 ID，是否表示所有数据都复制好了

不是。首先提示“请求已受理”，然后跟踪系统盘和数据盘复制；只有平台返回完成状态才提示“克隆成功 · 数据复制完成”。

### 网络超时后会不会重复下单

查询请求可以有限重试；付费创建请求不自动重发。若创建请求超时、响应无效或被中断，程序会停止并要求到官网核查。确认有没有新实例之前，不要直接重新启动购买流程。

### 停止脚本，会停止扣费吗

不会。脚本负责监控和创建，不提供累计预算控制或自动关机。已运行的新实例需要按实际使用情况在 AutoDL 控制台管理。

## 发布到 GitHub 前

**登录后的 `config.json` 包含授权令牌，配置了微信推送时还会包含 SendKey。只发布 `config.example.json`，不要上传个人配置。**

将以下内容加入 `.gitignore`：

```gitignore
/config.json
/venv/
__pycache__/
```

如果 `config.json` 已被 Git 跟踪，仅添加忽略规则不会取消跟踪。可在发布前执行下面的命令，保留本地文件并从暂存版本中移除：

```bash
git rm --cached config.json
```

同时检查待提交的日志、截图和历史提交，避免包含账号认证信息。本 README 的示例不包含个人实例 ID 或登录令牌。
