# autodl-monitor

在终端里监控 AutoDL GPU 库存，或等待合适机器后自动新建、克隆一个实例。优先支持 macOS。

**本项目基于 [Jiayi-Fu/autodl-gpu-monitor](https://github.com/Jiayi-Fu/autodl-gpu-monitor) 二次开发。** 保留其资源监控、登录和普通新建基础功能，扩展统一交互入口、实时地区和镜像选择、费用核验、同配置克隆、macOS 提醒及任务恢复。感谢原作者。

## 开始使用

本机安装 [uv](https://docs.astral.sh/uv/)，然后：

```bash
git clone https://github.com/Sykerai/autodl-monitor.git
cd autodl-monitor
./run.sh
```

启动脚本会在需要时建立 Python 3.12 环境并安装依赖。不需要手动激活环境，也不需要复制或编辑配置文件。

启动后先选择模式：

```text
autodl-monitor

1. 仅监控
2. 自动新建
3. 自动克隆
4. 恢复未完成任务
5. 设置 / 登录
6. 退出程序
```

输入数字选择，`b` 返回上一步；列表支持 `/关键词` 搜索、`n` / `p` 翻页，输入 `/` 清除搜索。多选地区时输入逗号分隔的序号，例如 `2,1`；顺序用于同价机器的地区优先级。输入错误会提示重选。

终端展示按选择、确认、运行三个阶段排版：列表名称和环境信息分行显示；任务摘要将资源、环境、费用分组；每轮库存汇成状态卡，创建受理和完成结果单独展示。长镜像名和实例 ID 会随终端宽度换行，输入区与说明分开。支持颜色的终端会使用轻量强调色；重定向输出或设置 `NO_COLOR=1` 时使用纯文本。

无参数启动始终进入菜单，**不会根据上次保存的购买模式直接下单**。原有 `config.json` 会继续读取，之后由程序自动保存偏好；没有配置时自动建立默认值。

## 三种模式

| 模式 | 要选择什么 | 会做什么 |
| --- | --- | --- |
| 仅监控 | 一个或多个地区、一个 GPU 型号、每台卡数 | 持续检查，有可租机器时提醒，不下单 |
| 自动新建 | 一个或多个地区、一个型号及卡数、镜像、额外数据盘容量、费用上限 | 按条件等待，自动新建一个实例并跟踪就绪状态 |
| 自动克隆 | 一个已关机的按量计费源实例、费用上限 | 沿用源实例地区和完整资源配置，复制系统盘及数据盘到一个新实例 |

每个任务仅选择一个型号和卡数。地区从平台实时目录获取，名称覆盖对应地区的全部子区。GPU 菜单使用与官网相同的地区型号接口：仅展示所选地区列出的型号，保留暂时空闲为 0 的型号，并显示空闲／总卡数；不混入其他地区才有的型号。多选地区时取型号合集，相同型号合计库存。CPU 项目不在 GPU 菜单中。库存是查询时的快照，可能与稍后刷新的网页有短暂差异。

克隆模式不单独选择地区、型号、镜像和磁盘大小，不支持跨区或改变源配置。程序不会关闭源实例；需要先在官网将源实例关机。现有非标准系统盘等无法保证同配置的情况会明确拒绝。

### 登录

需要访问账号时会引导登录：

- **粘贴 authorization**：输入隐藏，验证成功后保存到本机。
- **微信扫码**：显示二维码，在手机完成登录/授权；二维码窗口可以保持打开，程序会自动检测结果。

有效凭证会复用，失效后可在“设置 / 登录”更新。菜单也可以退出登录，清除本地凭证。手机号密码登录尚未验证，不作为本版菜单选项。

不要将 authorization、SendKey 或个人配置发到聊天、截图或提交 GitHub。

### 镜像和额外数据盘

自动新建提供两种来源：

- **官方基础镜像**：依次选择框架、框架版本、Python 版本、CUDA/环境版本。
- **我的私有镜像**：读取当前账号的镜像名称和环境，可搜索选择。

列表按所选 GPU 的芯片厂商和 CPU 架构筛选；真正选目标机器时，再检查架构、芯片、最高 CUDA 版本和扩容能力。镜像删除或环境信息变化时需要重新选择，不能静默替换成另一镜像。

新建可以选择额外扩容数据盘，例如 **增加 50 GB**。这里输入的是在平台默认容量之外增加的容量，默认不扩容；超过目标机器扩容能力的机器会被排除。

克隆直接使用源实例环境及磁盘配置，同时复制系统盘、数据盘，不另外选择镜像或扩容。社区镜像暂不包含在菜单中。

### 费用和下单确认

自动新建、自动克隆都必须设置上限，菜单默认 **3 元/小时**，每次都可以修改。

上限的口径为整个实例的折算费用：

```text
整实例 GPU 小时费用（含卡数、账号折扣） + 额外数据盘日费 ÷ 24
```

这不是单卡标价，也不是本次等待期间的消费总预算或租用时长限制。数据盘实际按平台规则计费，关机后是否仍收费以官网为准。创建成功后实例会继续计费，程序不会自动关机或释放。

程序排除配置/镜像不兼容及超预算机器，再按实时价格预览从低到高尝试，同价时按地区选择顺序。每次提交前重新核价，平台库存、价格仍可能在查询和提交之间变化，最终账单以 AutoDL 为准。

启动等待前展示完整任务摘要，并确认一次；确认后发现符合条件的机器会自动下单，不会再弹出第二次购买确认。**一次任务成功受理一个实例后就停止下单**，随后只读跟踪准备/复制进度。

## 等待、提醒与停止

没有合适机器时一直等待，直到用户按 `Ctrl+C`。终端显示检查次数、已等待时长、地区库存与最近结果。默认检查间隔 30 秒，可在设置菜单调整，网络错误有退避重试。

判断依据是逐台机器明细：空闲卡数满足单台需求、机器状态可租、实例容量未满。地区汇总与机器明细可能不同步，因此“汇总空闲1张”不保证一定能租到；多卡必须由同一台机器满足。

- macOS 弹窗和提示音默认开启。仅监控发现资源时提醒，默认至少间隔5分钟再重复。
- 自动新建/克隆主要提醒请求受理、就绪/复制完成、失败及需要处理的异常，避免库存弹窗打断抢机。
- 微信推送可在设置中输入 Server酱 SendKey；留空则关闭，不影响终端和本机提醒。
- 通知失败不会重新购买。

停止等待后可保留任务以便恢复，也可以结束任务。创建成功或停止后回到主菜单。退出程序不等于取消平台订单或停止实例计费。

## 任务恢复与防重复购买

程序在本地保存任务条件和进度；同一个配置目录只允许一个进程运行。任务文件不包含登录凭证。

在主菜单选择“恢复未完成任务”：

| 上次状态 | 恢复行为 |
| --- | --- |
| 尚未下单、已停止等待 | 展示原条件，重新确认后继续等待；也可以结束旧任务 |
| 已取得新实例 ID | 只跟踪这个实例，不再提交订单 |
| 提交途中退出、超时或响应无法确认 | 查询平台，列出可能匹配的新实例，要求用户核实；不自动再次下单 |
| 完成或明确失败 | 保留最近结果，可以建立新任务 |

在发送付费请求前，程序先原子写入“正在提交”和提交前实例列表；成功响应中的新实例 ID 也先落盘，再提醒、跟踪。这样进程重启仍知道是否存在未确认订单。

只有已知的库存/容量拒绝会自动回到等待；网络错误、缺失/异常新实例 ID、其他不明确响应都会保留待核实状态。**暂时没有查到新实例，不代表上次下单一定失败。** 必须先在官网核实，不能以重新运行代替核实。

结束本机任务记录不会取消、关闭或释放平台实例。还有未完成任务时，新任务会被阻止；请先恢复或处理旧任务。

克隆完成必须同时满足实例状态就绪和数据盘复制成功，“请求受理”不等于“复制完成”。本机单次跟踪达到时限或被中断，会回主菜单，之后可以恢复跟踪。

## 设置与本地文件

菜单可调整检查间隔、本机提醒、微信推送和登录。上次的地区、型号、卡数、镜像、扩容和费用上限会作为下一次的可编辑默认值，不需要维护 JSON。

| 文件 | 用途 |
| --- | --- |
| `config.json` | 自动维护的个人偏好及登录凭证；首次启动自动生成 |
| `.autodl-monitor/task.json` | 当前/最近任务的条件、提交状态和结果，支持恢复 |
| `.autodl-monitor/process.lock` | 防止同一配置目录重复启动 |
| `config.example.json` | 公开示例，仅供开发或高级用法参考 |

配置和任务使用原子写入，新写入文件权限为仅当前用户可读写。上述个人文件已加入 `.gitignore`。旧配置会沿用，保存偏好时不会用旧内存凭证覆盖刚更新的凭证。请勿删除未核实订单的任务文件。

macOS 是优先支持平台；Linux 可用终端和微信推送，本机原生弹窗未实现。扫码依赖能显示二维码的桌面会话。Windows 暂未验证。

## 保留的命令用法

通常只需 `./run.sh`。以下参数供高级用户使用，调用同一套库存、价格、下单和跟踪逻辑。

```bash
# 一次只读查询：不下单、不弹窗、不推送
./run.sh --once --region 北京B区 内蒙B区 --gpu "RTX 5090" --num 1

# 持续监控，临时覆盖地区/型号（个人配置应为仅监控）
./run.sh --region 北京B区 --gpu "RTX 4090" --interval 30

# 只测试弹窗，不登录、不查询、不下单
./run.sh --test-popup

# 列出账号实例
./run.sh --list-instances

# 重新扫码登录
./run.sh --login

# 指定其他本地配置；只给 --config 时仍进入菜单
./run.sh --config /path/to/personal/config.json

# 新建计划预览：镜像沿用此前菜单保存的选择
./run.sh --buy-preview --region 北京B区 --gpu "RTX 5090" --num 1 --extra-disk 50 --max-price 3

# 自动新建：需要在终端输入 BUY 确认
./run.sh --buy --region 北京B区 --gpu "RTX 5090" --num 1 --extra-disk 50 --max-price 3

# 克隆计划预览 / 自动克隆（将 INSTANCE_ID 换成真实 ID）
./run.sh --clone-preview --source INSTANCE_ID
./run.sh --clone --source INSTANCE_ID --max-price 3
```

克隆参数模式仍须输入 `CLONE` 确认，地区/型号/卡数/磁盘由源实例决定。付费模式不支持无终端静默授权。`--once` 始终只读。旧配置中的镜像地址字段为兼容保留，新菜单使用平台镜像 UUID。

带参数运行时保留旧配置 `mode` 的语义，因此旧用户应确认其值；无参数菜单不会据此直接执行。命令临时覆盖不写入偏好。`--help` 可查看完整参数。

## 开发与验证

```bash
uv venv --python 3.12 venv
uv pip install --python venv/bin/python -r requirements.txt
venv/bin/python -m unittest discover -s tests -v
```

测试使用隔离临时配置和模拟订单，覆盖地区/型号/镜像、扩容计价、价格变动、完整候选过滤、菜单返回、创建成功、通知失败、持久化、提交中断、重启核实与进程互斥。测试不会创建真实付费实例。

实际账号可验证地区、GPU、镜像和价格预览等只读接口；接口可读不等于已经做过真实购买测试。平台未提供稳定公开 SDK，网页接口可能变化；未知数据或费用缺失时会拒绝下单。

| 模块 | 职责 |
| --- | --- |
| `main.py` | 单入口、模式执行、监控和结果提醒 |
| `interactive.py` | 终端向导、选择/返回、设置及恢复操作 |
| `terminal_ui.py` | 中文宽度换行、菜单排版、任务和运行状态卡片 |
| `catalog.py` | 动态地区、GPU、基础/私有镜像目录 |
| `gpu.py`、`cloning.py` | 兼容条件、普通新建和同配置克隆 |
| `pricing.py` | 整实例费用预览、扩容计价和排序 |
| `task_store.py`、`local_state.py` | 任务状态、原子存储和进程互斥 |
| `instance_status.py` | 新实例只读就绪跟踪 |
| `watch.py`、`regions.py` | 库存和地区解析 |
| `login_helper.py`、`config_loader.py` | 登录和自动设置 |
| `desktop_alert.py`、`notifications.py` | macOS 弹窗和 Server酱推送 |
